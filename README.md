# Everywhere

Everywhere 是一款面向 iPhone 和 iPad 的定位模拟工具。你可以在 macOS 或 Windows 控制台的地图上选点，通过 USB 或 Wi-Fi 为已配对的设备设置、更换或清除模拟位置，也可以在移动端遥控主机，并用 Core Location 样本核对设备实际报告的位置。

Everywhere is a location simulation tool for iPhone and iPad. Pick a point on the map in the macOS or Windows console to set, change, or clear a paired device’s simulated location over USB or Wi-Fi. The mobile app can also control the host and show the location the device reports through Core Location.

Apple 端源码位于 `swift/`，Windows Qt 端源码位于 `windows/`。从项目根目录执行 `./package.sh` 导出 Apple 版本；Windows x64 使用 `package-windows.ps1`。

Mac 上的 SwiftUI 控制台向用户已配对的 iPhone 或 iPad 发出定点和清除请求。Everywhere 内置诊断页，显示本机从 Core Location 收到的位置样本和当前网络路径。手机遥控可以选择 Wi-Fi 或 USB。USB 和 Wi-Fi 都只允许操作已绑定的本机。

iPhone 与 iPad 在 Everywhere 中连接 Mac 后只能设定和恢复自己的位置。首次用 USB 在 Mac 开启这台设备的连接，手机自动取得本机绑定。之后连接同一 Mac 的 Wi-Fi 服务时沿用该绑定；未绑定的网络连接只能查看连接状态。需要同时更新 Mac 控制台。

## 检查本机定位来源

在 iPhone 上打开 Everywhere，在「本机定位来源」点击「开始检测」，允许使用期间定位。每条 Core Location 样本分别显示 `isSimulatedBySoftware` 和 `isProducedByAccessory`。软件模拟字段为 `true` 时显示警告；来源缺失时显示「未知」。停止检测或进入后台后，面板保留最后一条样本及时间。该检测可独立于 Mac 连接使用。

点地图左上角「诊断」可查看坐标、水平精度、样本时间、来源标记及网络对照。首页和诊断页共用一轮定位监听。真机比较 Wi-Fi 接入点时，签名需要支持 Access Wi-Fi Information。

## 恢复定位

在 Mac 控制台选择目标，或在已连接的手机上直接点击本机操作区的「恢复真实定位」并确认。保持执行链路在线，收到停止模拟回执后在目标设备打开地图、点“我的位置”，也可以在 Everywhere 的「诊断」中查看最新样本。如果仍停在旧位置，可手动重启该设备后复查。若命令超时或连接中断，请重新连接同一目标，刷新设备后再次执行恢复。

蓝牙接收模式显示「清除蓝牙位置」，Mac 可移除手机应用标记，接收可继续。模拟器显示「清除模拟器定位」，随后可能没有可用位置样本。

## Mac 模式与地图选点

启动时选择「蓝牙配件模式」或「软件模拟模式」。软件模拟默认自动列出 USB 和 Wi-Fi 设备，直接点选手机。发布包内置 Python 运行时及开发定位服务，目标 Mac 可在未安装 Xcode 的情况下设点、换点和清除。会话结束后可在右侧返回模式选择。使用大陆偏移底图时，选择 GCJ-02，地图点击将反算到 WGS 84；原生 WGS 84 底图选择 WGS 84。手工输入、地点簿和发往手机的坐标均为 WGS 84。

**发送选点**。Mac、iPhone 和 iPad 每次发送或更换选点时都会显示定位服务操作说明。点击「我已知晓」才会下发本次命令，点击「取消」可返回地图。

**首次连接新机**。解锁 iPhone，通过 USB 数据线接入 Mac，在「设备」列表点选对应设备。要使用无线连接，点击「信任设备并启用 Wi-Fi」，在手机上确认信任。两端处于同一局域网后拔线，等待同一设备显示 Wi-Fi。软件模拟按手机提示开启开发者模式，首次准备匹配的开发镜像可能需要联网。iOS 17.0–17.3 的独立隧道还需要已有的 RemotePairing 记录，17.4 起支持通过已信任的 USB 开始准备。

## iAP2 蓝牙配件定位（实验）

Mac 版内置蓝牙客户端、RFCOMM 桥和 MFi v3 认证程序。配件证书与匹配的签名私钥位于 App 内的 `Contents/Resources/asset/mfi/`，复制 Mac App 即携带这套可复制的签名身份。在启动页选择「蓝牙模式」，在设备页选择「iAP2 配件」，让 iPhone 停留在「设置 → 蓝牙」，从 Mac 点击「连接新 iPhone」卡片。在设备栏内点选手机后，Mac 直接建立经典蓝牙连接，查询 iAP2 服务并执行配件认证。若系统提示配对，请在系统界面完成确认。控制台显示「配件认证通过」表示 iPhone 已接受本次身份。已有外部程序仍可在「认证程序」中选择。

在 iPhone 的 Everywhere 打开「连接设置 → 蓝牙 → 手机扫描 Mac」，选择执行 iAP2 的那台 Mac，即可通过加密的只读蓝牙服务看到 Mac 所选设备、握手、认证、失败与结束状态。这条状态通道不需要接收码；系统是否采用坐标仍在「本机定位来源」中观察。

在「已有iPhone连接」下拉框选择已配对的手机即可连接并验证 iAP2。连接结束或失败后，再次选择同一台手机即可重试。认证与识别完成后，控制台保持同一条连接，点击「发送地图选点」并确认才提交坐标。在 Mac 地图选点，点击「发送地图选点」，在 iPhone 上打开地图并请求当前位置。控制台依照客户端事件显示认证、位置请求和链路回执。发送会话在识别和认证完成后持续保持连接；手机暂停订阅时暂停发包，恢复订阅后继续。短暂断线时，发送会话会在 2 秒和 5 秒后最多重连两次。重新认证后点击「确认选点并继续发送」，待手机重新订阅后恢复发送。可随时点「停止会话」；更换地点后再次点击「发送地图选点」，在同一连接等待新坐标的回执。手机端的系统采纳与恢复均需用独立的 Core Location 样本核对。内置程序、对应源码与许可证随 App 分发。上游版本和打包说明见 swift/Host/IAP2Client。构建机用 EVERYWHERE_IAP2_PYTHON 指定装有 PyInstaller 6 的 Python 3.11+；使用安装包的 Mac 无需安装 Python。

## 蓝牙直连

手机在「连接设置 → 蓝牙」点「让 Mac 扫描本机」，在前台完成首次连接。Mac 打开打包的控制台，在「蓝牙模式 → 设备」选择「Mac 扫描手机」，点击「扫描蓝牙设备」、选中手机并点击「连接手机」。显示「控制台已连接」后，输入手机显示的六位接收码。两端更新到新版后，手机首页和连接设置在蓝牙服务订阅成功时即显示「蓝牙已连接」，独立于后续坐标回执。扫描同时列出附近广播和系统已连接的定位接收端；系统连接状态取自本次扫描，控制台持有的连接会跟随断开事件更新。两端系统设置只需打开蓝牙。然后从地图应用固定点、更换坐标或清除。首次加密连接时按系统提示配对。此路径可在拔掉 USB 和关闭 Wi-Fi 后使用。

新版两端会协商 NMEA GPRMC 格式，设点携带 UTC 时间与日期、WGS 84 经纬度、模拟模式标志和 XOR 校验和。接收端校验成功后更新应用地图。旧端点或单包容量不足时沿用紧凑坐标；清除沿用独立控制命令。该格式运行于 Everywhere 的 BLE 服务，系统级定位仍由 USB 或 Wi-Fi 开发连接执行。

手机收到写入后先更新应用内的“蓝牙位置”，再返回回执。接收码只在本轮有效，首个通过校验的 Mac 持有本轮接收权。锁屏、返回主屏幕或切换到其他应用后继续接收系统派发的蓝牙事件。关闭接收或切换连接模式会清除标记并撤销接收码。用户从多任务界面强制退出或系统终止进程后，本轮接收结束，需要重新打开并连接。已有 Mac 会话时，先在 Mac 清除位置再切换后端。手机开启新一轮接收后，可在 Mac 重新输入接收码并清除旧会话。

蓝牙验收观察手机地图依次显示 A、B 并在清除后移除标记。USB、Wi-Fi 的系统开发定位使用内置「诊断」读取系统位置验收。普通 BLE 接收端只更新本应用的位置。手机返回前台后可点「开始检测」，查看新系统样本与蓝牙标记的距离及水平精度。Mac 蓝牙权限说明随 `package.sh` 打包写入应用。

手机也可主动发起蓝牙连接。在 Mac 的「蓝牙模式 → 设备」选择「手机扫描 Mac」并开启广播，在手机点「手机扫描 Mac」并选择对应主机。系统提示时确认蓝牙配对，再在 Mac 输入手机的六位接收码。坐标更新和清除均以手机应用回执为准。

如果大陆偏移底图上的地标与已知 WGS 84 坐标错位，可在地图图层菜单将「底图坐标系」切换为 GCJ-02 并重新选点。默认使用 WGS 84。点击和搜索结果按所选底图坐标系转换，手输、收藏及发送给设备的坐标统一使用 WGS 84。旧收藏缺少坐标来源，原先在错误模式下存下的点需要重新选取。

## 导出 IPA 和 Mac App

构建机需要完整 Xcode（含 iPhoneOS SDK）、Python 3.11+、PyInstaller 6.x。软件定位后端固定为 `pymobiledevice3==11.62.0`，两个 Python 辅助程序随 App 分发。本地 ad-hoc 构建会复用最近完整导出中签名有效、源码、依赖声明、脚本与 CPU 架构均匹配的软件定位辅助程序。显式指定后端解释器会强制重新构建。首次构建将依赖安装到 `Build/` 下的专用虚拟环境，也可用 `EVERYWHERE_IAP2_PYTHON` 和 `EVERYWHERE_PORTABLE_PYTHON` 指向准备好的解释器。Mac App 内含可读取的配件私钥，iOS 分发签名材料只在构建机使用。

从项目根目录执行

```sh
./package.sh
```

使用 `./package.sh --mac-only` 或 `./package.sh --ios-only` 可只导出一个平台。单平台构建输出到独立目录。

默认完整打包从固定目录 `Build/Everywhere/` 获取最新一次成功导出的产物。该目录链接到 `Build/Exports/` 下对应的历史版本，包含 `Everywhere.ipa`（iPhone / iPad 通用）、已签名的 `Everywhere.app`（当前 Mac 架构）和方便传输的 `Everywhere-macOS.zip`。脚本会解压 ZIP 并验证其中的 App 签名。项目的 `asset/ios-signing/` 目录存放一份 P12 证书和对应的描述文件。签名时优先读取环境变量 `EVERYWHERE_IOS_P12_PASSWORD`，其次读取该目录的本机文件 `p12-password`，两者都缺少时在终端提示输入。签名后的安装包为 `Everywhere.ipa`，原始包为 `Everywhere-unsigned.ipa`。签名副本使用描述文件授权的应用标识。缺少证书目录时仍可导出未签名 IPA。

Mac 默认使用 ad-hoc 本机签名。如已有自签代码签名证书，可指定钥匙串中的身份名称或指纹。可选参数为导出父目录。

```sh
MAC_SIGN_IDENTITY="你的代码签名证书名称" ./package.sh "$HOME/Desktop/Everywhere"
```

通过浏览器下载时，接收方的 Mac 可能给 ZIP 添加 `com.apple.quarantine` 隔离属性，系统解压工具也可能将其传给 App。在打包机上移除这一属性无法保证接收方直接打开。若需通过 Gatekeeper 验证开发者身份并公开分发，应使用 Developer ID Application 证书签名并完成 Apple 公证。[Apple 分发说明](https://developer.apple.com/developer-id/)

若在已有外层沙箱的构建环境中遇到 `sandbox_apply: Operation not permitted`，可用 `EVERYWHERE_NESTED_SANDBOX=1 ./package.sh` 运行。

## Mac 直接给已配对的设备无线设点

高级设置中的「仅 Wi-Fi（Xcode）」沿用 Xcode 路径。在 Xcode 的 Device Hub 中完成 iPhone 或 iPad 配对，确认开发者模式和开发服务可用。将 Mac 与设备接入同一局域网，拔掉 USB 线，打开控制台的「设备 → 执行后端 → 已配对真机 · Wi-Fi」，点击「刷新无线设备」，再从列表选择目标。回到地图即可定点、换点、清除；目标设备无需运行遥控 App，Mac 也无需开启遥控监听。

该入口使用 Xcode 的 `devicectl device simulate location coordinate/clear`，已核对 Xcode 27.2 命令接口。仅列出 CoreDevice 报告为局域网连接的已配对 iPhone / iPad，执行前再次核对 UDID 与连接类型；查询结果仅表示当次发现。工具版本须提供上述子命令。清除后以目标设备 Everywhere 诊断页的新样本验收。

## 通过公网连接遥控服务

Mac 在「设备 → 手机遥控 → 网络遥控」设置 TCP 端口（默认 49372），点击「开启网络遥控」。端口下次启动保留；更换端口先停止监听。启用 Bonjour 可同时在局域网发现主机，手动地址连接直接使用同一个 TLS 服务。

在有公网入站能力的网络中，允许客户端到达该 TCP 端口。Mac 在 IPv4 路由器后时，把公网 TCP 端口转发到 Mac 的局域网地址和监听端口；公网 IPv6 可通过可路由地址及对应防火墙入站规则直达。运营商共享 IPv4 且没有入站映射时，可采用可达的 IPv6 或已有的 TCP 转发入口。服务端显示的是本机监听状态，公网可达性应通过外网客户端验证。

移动遥控选择「Wi-Fi → 手动输入地址」，填写公网域名或 IP、**外部 TCP 端口**和 Mac 的配对码。该连接也可通过移动数据建立。配对码由 Mac 单独提供，可在 Mac 撤销。公网只需转发遥控服务端口，设备开发工具连接仍由 Mac 在本地发起。

## 手机选点，由在线 Mac 执行

1. 从项目根目录运行 `./package.sh` 构建两个平台。启动 Mac 控制台：

   ```sh
   open Build/Everywhere/Everywhere.app
   ```

2. 在 Xcode 打开 [Mobile.xcodeproj](swift/Apps/Mobile/Mobile.xcodeproj)，选择 iPhone 或 iPad（iOS/iPadOS 17+）。真机首次运行须配置开发团队与唯一 Bundle ID。Mac 保持唤醒，控制台保持运行。
3. 在 Mac 控制台切到“设备”，或点击固定底栏的“选择设备”，按下表连接。Mac 可以同时开启两种遥控，手机在“连接 Mac”中选择一种。首次连接时输入 Mac 面板“显示配对码”中的凭据。

| 方式 | Mac 上的设置 | 手机上的设置 |
| --- | --- | --- |
| Wi-Fi | 准备已绑定的本机真机目标，点击“开启网络遥控”。如需在 Mac 按手机 IP 核实无线开发连接，在 Wi-Fi 后端输入 iPhone 的 IP 并点“验证连接”。 | 接入同一局域网并允许本地网络访问。默认可手动输入 Mac 的 IP 和监听端口，也可选择 Bonjour 主机。已有 USB 绑定时可选择“使用已保存的 USB 配对连接”。 |
| USB | 用数据线接入已信任的 iPhone/iPad，点击“连接 USB 手机”。单根线自动识别，多台设备时先选定目标。 | 选择 USB，输入配对码并点“开启 USB 接收”，保持应用在前台。Mac 通过本机 usbmuxd 连接手机 App，双方通过 TLS 验证。无需输入 IP 或额外安装 iproxy。 |

4. 手机显示“已绑定本机”后直接选点。搜索、点按地图、输入经纬度或调出收藏，再点击“应用到本机”。换点时再次应用，结束时点击“恢复真实定位”。切至其他 App 后，Mac 继续管理会话。手机回到前台时尝试恢复控制连接并查询状态。
5. 在目标设备打开 Everywhere 的「诊断」，查看 Core Location 样本。对照操作时间、坐标与水平精度，分别记录设点的首次新样本和清除后恢复的样本。

配对码存入钥匙串。手机“忘记此 Mac”删除当前方式的本地凭据，Mac“撤销配对”使两种方式的旧凭据同时失效。检测到拔线后，有活动会话的设备会显示结果未知。重新连接同一台设备后，请先清除再设点。单纯退出手机遥控界面不会触发清除。

### 搜索、收藏与最近使用

Mac、iPhone 和 iPad 的地图上方有搜索和图层菜单，目的地卡片下方可打开收藏与最近使用。地点搜索使用 MapKit，可输入地名、地址或地标。点选结果会将地图移到该点并更新草稿。收藏可自定义名称、重命名、移除，也可以打开地图收藏标记。图层菜单可切换标准地图和卫星地图。

“最近”保留本机最近成功应用的 20 个不同模拟地点，重复使用的地点移到最前。可单独清空最近使用记录。收藏和最近使用分别保存在各端本地。选择地点、保存收藏和浏览地图均可在连接 Mac 之前完成。

### 既有模拟器验证记录（本机绑定改动前）

在地图选点或输入十进制经纬度，检查目标设备后再应用。改点时提交新的草稿。结束操作时主动清除，保持设备连接并在 Everywhere 的「诊断」中检查后续新样本。若主机断电或设备失联，请在重连后向同一设备显式清除。重新启动控制台后，从最近一次清除结果和新样本判断是否恢复，避免根据空白界面推断设备状态。

桌面和手机共用每台设备的定位会话。收到设点回执后两秒内再次提交完全相同的经纬度，控制台提示复用已有回执；超过两秒可主动重发。断线后的未知会话须先清除。现代 USB 辅助进程仅在首次就绪前遇到连接错误或超时时额外尝试一次，两次合计最多等待 75 秒；重试前释放通道并重新核验 USB 身份。

## 判读结果

1. 在实际地点 A 启动独立 Probe，记录定位权限、样本时间、精度与来源。
2. 在 Mac 上依次设两个相距明确的点 B、C。观察每次操作后 Probe 是否收到对应的新样本，并单独记录朋友圈“所在位置”的默认附近地点。
3. 清除后分别记录工具返回时间、首个恢复 A 的新样本时间。拒绝权限、旧缓存样本和默认地点未变化要单独记录。

主机工具回执、系统定位样本、朋友圈界面是三个独立观测。本项目当前没有经真机验收的兼容性组合。
