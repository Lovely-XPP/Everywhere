# LocationProbe 开发对照工程

用户版已整合到 Everywhere，入口为地图左上角「诊断」。以下工程保留供开发时独立观察，不随移动端安装包分发。

独立的 iOS / iPadOS SwiftUI App，在前台独立读取 Core Location 位置样本，支持对照默认网络路径和当前 Wi-Fi 接入点。它不依赖 Mac 主机、设备执行后端、模拟位置输入或第三方应用。工程配置的最低部署版本为 iOS / iPadOS 15.0；这是 API 可用性选择，尚不是经过真机验证的兼容性结论。使用带 Swift 6 编译器的 Xcode 打开工程。

## 使用 Xcode 打开和签名

1. 双击本目录的 `LocationProbe.xcodeproj`（无需生成工程或下载 Swift Package）。
2. 选择工程内的 `LocationProbe` Target，在 **Signing & Capabilities** 选中自动签名，并选择你的开发团队（Team）。如 Bundle Identifier 已被占用，改为你的唯一标识。
3. 使用受你信任的 Mac 连接自己的 iPhone 或 iPad，选择该真机作为运行目标。按 Xcode 和设备给出的提示完成开发机准备与签名。
4. 选择共享的 `LocationProbe` Scheme 并 Run，首次点击 App 中的“开始监听”时，允许使用 App 期间访问位置。此 Scheme 默认不启用 Xcode 的定位模拟，避免诊断工具自身引入位置变化。

真机默认签名使用 Access Wi-Fi Information 能力，用于比较设点前后的接入点。如团队无法签发该能力，可在目标的 Code Signing Entitlements 中清空 iPhoneOS 条目，继续使用定位和网络路径观测；Wi-Fi 接入点将显示未取得。如果不给定位授权，App 会显示对应状态；可在设备的设置中自行修改授权并返回 App 重试。

## 读取观测值

| 字段 | 语义 |
| --- | --- |
| 定位权限、精度授权 | 系统授予 App 的权限，不等同于单个样本的精度。 |
| 纬度、经度 | Core Location 样本的坐标，单位为度。无效坐标不用于位置确认。 |
| 样本时间、接收时间 | 分别为系统样本时间和 App 回调接收时间；均以 UTC（毫秒）显示。 |
| 接收与样本时间差 | 两者相减，秒。负值提示核对设备时钟。 |
| 水平精度 | 米；无效精度不展示为有效数字。 |
| 软件模拟来源、配件提供来源 | `CLLocation.sourceInformation` 中的布尔值；如未提供则为“未知”，不解释为“否”。 |

“正在监听”仅表示已调用 `CLLocationManager.startUpdatingLocation()`，不代表收到新样本。若最新样本的时间早于本轮监听开始时间，界面会提示可能是缓存样本。位置来源字段与其他应用的位置表现应分别记录，不能据此判断其他应用如何识别或使用位置。

“停止监听”不会修改定位权限或系统位置；最后一条样本仍显示，方便人工读数，下一轮开始时清除。转到后台会停止，返回后需重新点击开始。App 不持久化或上传真实位置，不保存样本历史，也不申请后台定位权限。

## 比较设点前后的网络

在设点前、换点后和清除后，分别按“读取网络样本”。当前路径来自 Network 框架；Wi-Fi 和蜂窝是网络接口类型。真机通过系统接口读取当前接入点，并同本次运行首次可用的 BSSID 比较。读不到标识时保留未知；同一网络也可能在多个接入点间漫游。比较结果不包含基站坐标或 Wi-Fi 地理坐标。BSSID 仅在内存中比较，关闭探针后基线释放。模拟器可以测网络路径，实体接入点需在真机测试。

2026-11-24 使用 iPhone 18 Pro 模拟器（iOS 27.2）实测。设点前默认路径为 Wi-Fi。深圳样本为 22.543096、114.057865，悉尼样本为 -33.868820、151.209290；两次来源均为软件模拟，取样时默认路径均为 Wi-Fi。清除后重新订阅，显示等待新样本及早于订阅的缓存坐标。模拟器不具备实体接入点对照条件；真机目标已完成无签名编译，尚未实测 BSSID。
